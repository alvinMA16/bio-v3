# 平铺资料夹与私有 OSS

资料夹不支持子文件夹。Web 用照片相框、文档纸张卡片展示文件名、类型和大小；支持搜索、分类、最多 20 份逐项上传、失败重试、打开原件、删除确认和资料对话入口。每份文件上限 20 MB。小程序复用同一 API，显示相同风格的平铺卡片；上传仍使用原有单文件选择流程。

支持 JPEG、PNG、WebP、PDF、DOC、DOCX、UTF-8 TXT 和 MD。图片生成最长边 480 像素的 WebP 缩略图并纠正 EXIF 方向；PDF 尽量渲染第一页并记录页数。Word、文本和不能渲染的 PDF 使用简洁纸张图形，不在缩略图中展示正文摘录。所有卡片将类型和大小收在缩略图底部。资料夹为完整页面，顶部保留紧邻的返回、标题与搜索图标，点图标进入独立搜索页，底部玻璃悬浮岛放置全部／照片／文档分类和加号添加入口，列表预留底部空间，小程序适配底部安全区；与主场景一致的灰白毛毡底、无框标题与植物纸页呼应书桌素材，去掉套层面板与封边，不绘制模拟系统胶囊，小程序导航按真实胶囊尺寸留出右侧空间；不提供拖拽上传。原件保持不变。无视觉识别配置时不宣称理解图片；不在预览页提供手动说明编辑。

## 存储与隔离

开启 `MATERIAL_STORAGE=oss` 后，新上传的原件和缩略图存放在：

```
bio-v3/users/<SHA-256(服务端内部用户ID)>/materials/<服务端生成的UUID>/original
bio-v3/users/<SHA-256(服务端内部用户ID)>/materials/<服务端生成的UUID>/thumbnail.webp
```

此目录与 `bio-v3/assets/` 界面素材、Calendar 对象分开。目录哈希不构成权限验证；真正的边界是登录身份和服务端归属检查。

- 对象固定为 private，禁止覆盖，客户端没有 OSS 访问密钥。
- 接口只接受资料 ID；用户 ID 来自认证会话，路径由服务端生成。
- 列表、详情、原件、缩略图、修改、删除及模型读取都限制当前用户。归属不匹配返回 404；未登录返回 401。
- 原件和缩略图经过鉴权接口读取，由服务端从 OSS 获取内容；不返回长期公开 URL，也不允许界面素材 CDN 签名入口访问用户目录。
- Web 图片使用 HttpOnly 登录 Cookie，显式 Bearer 优先；小程序下载图片时携带 Bearer。响应设置 `private, no-store` 和 `nosniff`。
- 只有原件与缩略图都成功保存后才发布元数据。失败会尝试清理本次新对象；删除会先删除 OSS 内容再删除元数据。
- 标题、归属和提取正文等元数据仍保存在现有用户隔离的服务端持久卷。备份必须同时考虑元数据与 OSS 对象；现有文件备份脚本不会复制 OSS 中的原件。

本地开发默认 `MATERIAL_STORAGE=local`；启用账号的 production 环境默认要求 OSS，缺少配置会阻止启动，避免悄悄把新文件存回本地。旧本地资料继续可读，不会因为切换配置而丢失；本次没有自动迁移旧资料。若元数据声明对象存于 OSS 而密钥未配置，明确报错，不降级为其他用户或目录。

## 部署配置

仅在服务器私有环境文件中设置：

```
MATERIAL_STORAGE=oss
MATERIAL_OSS_REGION=oss-cn-beijing
MATERIAL_OSS_BUCKET=calendar-images
MATERIAL_OSS_ACCESS_KEY_ID=<服务端密钥>
MATERIAL_OSS_ACCESS_KEY_SECRET=<服务端密钥>
```

当前通过 Calendar 的服务端配置完成连通性验证，未创建新的 RAM 身份或修改桶策略。后续配置独立 RAM 凭证时，权限仅需此桶 `bio-v3/users/*` 下的 GetObject、PutObject 和 DeleteObject。无需允许客户端列举桶，不关闭桶的公共访问阻止策略。应用内按用户隔离仍然必须执行，RAM 前缀限制不能替代它。

## 验证

`materials.test.mjs` 覆盖真实 PDF/DOC/DOCX 文件、缩略图和原件保留；`materials-oss.test.mjs` 覆盖私有路径、隔离、重启读取、部分失败清理；账号数据库测试覆盖原件与缩略图的 Cookie/Bearer 权限边界。

真实 OSS 的显式验收（只创建合成用户文件，结束后清理）：

```sh
MATERIAL_OSS_LIVE_EVAL=true node apps/api/test/materials-oss-live.mjs
```

需要上述 OSS 配置。验证实际上传/读取、跨用户拒绝和匿名 OSS URL 返回 403，不使用真实用户文件。

分类高亮使用同一玻璃块滑动并轻微回弹；列表先退场，再按序进入，不展示独立数量行。快速切换只提交最后一次筛选，页面退出清理定时器。减少动态效果偏好下关闭位移与回弹；不支持背景模糊时使用可读的浅色底。

搜索页只显示文件名匹配结果，默认不显示全部资料；停止输入 1 秒后筛选，键盘搜索立即执行。新输入取消旧定时器，清空、返回和卸载清理等待；Web 中文输入法合成期间不触发搜索。搜索覆盖所有分类，使用已鉴权加载的当前用户列表，不随按键发起网络请求。

搜索输入采用透明底与细灰色底线，移除通用绿色焦点框；资料卡、照片边框与玻璃导航统一降低黄色饱和度，保留毛毡纹理。

文件打开后进入独立全屏预览，返回直接回资料夹；顶部显示文件名与删除入口。图片按原比例展示原图，PDF 按需渲染当前页，支持上一页、下一页和页码显示，保留打开原件入口，Word／文本显示提取文字并标注文字预览；小程序 PDF 同样支持页内翻页，并可用原生查看原件。预览页不提供名称与说明编辑，底部用令狸半身形象搭配“和令狸聊聊”入口，删除需确认，成功后移除列表项。

聊天入口使用独立生成的令狸透明半身素材 `assets/materials/lingli-chat.webp`，不再裁切动画帧；删除入口为带无障碍名称的垃圾桶图标，保留确认流程。

资料卡长按显示“预览／和令狸聊聊／删除”，删除需二次确认；Web 同时支持右键与 Shift+F10。移动超过 10px 或触摸取消会撤销 Web 长按，长按松手不会误打开预览；小程序使用原生 longpress 触发自定义菜单。两端菜单均以略微倾斜的缩略图和文件名卡片悬浮在上方，下方预览、聊天、删除、取消等宽居中，背景轻微虚化。搜索结果复用同样的操作。

上传提示使用浅苔绿色；每份成功记录显示约 2.8 秒后自动淡出并移除，不提供手动收起按钮。上传中与等待中的项目持续显示，失败项目保留错误和重试入口。普通操作提示 4 秒后自动消失。

PDF 翻页接口 `GET /materials/:id/pages/:page` 复用原件归属校验和 Cookie/Bearer 鉴权，拒绝无效与越界页码；返回当前页 WebP 与实际总页数，禁止共享缓存。Web 切页或关闭时取消请求，小程序忽略过期响应并清理临时预览文件。

图片与 PDF 使用完整画面适配：横版在可用阅读区居中，竖版以整页高度为限、两侧留白，不裁切或拉伸；PDF 翻页在下方独立占位。文本提取预览继续滚动阅读。

聊天入口使用新版 `apps/miniprogram/miniprogram/assets/materials/lingli-chat-wave.webp`，原版保留。内置 image_gen 编辑生成，提示词：保留原令狸针毡毛发、橙白配色、墨绿马甲和米白衬衣，改成略微侧身前倾、歪头微笑、一只爪子在脸旁招手、另一只靠近下边缘；半身构图，耳朵与手完整，真实透明背景，无文字和额外道具。新版素材当前走打包静态路径，下一次发布 OSS 清单时一并纳入。

## 资料聊天与模型历史

点击“和令狸聊聊”进入现有语音聊天界面，携带 `context.materialIds` 和附件场景；Web 先显示所选附件，服务端按当前登录用户解析文件并立即切换附件面板。小程序路由使用 `mode=call&materialId=…`。

以下正文快照路径仅保留给调试台手动选择的非 Gemini 提供方；资料夹聊天默认选择 Gemini，走下一节的原生文件路径。

每个附件内容版本首次加入会话时，在 SDK `session.jsonl` 写入 `custom_message / bio_material_attachment`，记录资料 ID、版本化附件 ID、名称、类型、提取正文前 6000 字、截断标记与表示方式。记录参与后续模型上下文；同版本不重复写入。完整提取正文保存在会话 `panel.json` 的附件表中，模型用 `get_content(attachmentId)` 按需读取（上传提取上限 10 万字）。PDF/DOC/DOCX 传提取正文，不把原文件二进制假装成文字；PDF 翻页渲染与聊天文本读取是两个功能。

视觉模型另接收真实 JPEG 图像内容块（长边最多 1600 像素，服务端鉴权读取原图后生成），随附件记录持久化。非 Gemini 提供方需显式设置对应 `*_SUPPORTS_IMAGES=true`，仅用于实际支持图像的模型。文本模型只有已有识别文字及状态提示，不能声称看到了原图。无正文的扫描件或未识别图片会明确保留识别失败/未识别状态。附件内容作为用户资料处理，不视为系统指令。

每轮请求前另插入 `bio_runtime_context`（活动附件前 6000 字、附件索引、界面模式），该临时消息本身不写入会话历史。附件快照与原件独立，删除资料夹原件不会自动删除已存在的会话记录。集成测试检查 SDK 实际向模拟模型发送的正文与 image_url 内容、会话恢复和快照去重；不以模型随口声称“看到了”作为验收。

## Gemini 原生附件与附件通话

Gemini 使用 Files API 上传完整原件（图片、PDF、UTF-8 文本），不根据字数或文件大小切换 inline。DOC/DOCX/PPT/PPTX 通过 LibreOffice 转成 PDF；生产镜像安装 Writer、Impress 和中文字体，本地可配置 `LIBREOFFICE_BIN`。转换失败明确报错，不退回正文截断。PPT/PPTX 上传时转换并生成首页缩略图，模型和预览共用转换结果。

`session.jsonl` 的 `bio_material_attachment` 记录稳定的 materialId、attachmentId、标题；Google 临时引用仅保存在服务端账号与凭据隔离的缓存中。Pi 的 context 扩展在历史原位置恢复附件标记，provider payload 扩展转换为 `fileData: {fileUri, mimeType}`。每轮及工具循环保留引用，不重复追加附件消息；压缩后恢复文件引用。Files 引用在过期前 5 分钟从原件重传，正常有效期由 Google 返回（通常 48 小时）。Files 上传复用不等于模型 token 缓存。每次使用缓存前仍验证资料归属和存在性；Google 上的临时副本按其到期时间清除。

网页和小程序附件通话以文件为主区域，不展示说话字幕；多页翻页位于文件下方，单页/图片不占翻页栏。专注查看收起小窗和通话操作，保留退出入口，不断开语音。图片/PDF 支持双指 1–4 倍缩放、放大后拖动、双击缩放/恢复；翻页恢复整页。网页资料夹预览也复用缩放组件。客户端每轮可提交 `attachmentView: {materialId, page}`，仅与当前资料匹配时作为“正在看哪一页”的客户端提示，不裁剪模型的文件输入。

验证：`gemini-files.test.mjs` 使用本地模拟 Google 服务检查原始上传字节、多轮及工具循环引用、会话恢复、压缩恢复、过期重传、并发去重、用户隔离和失败关闭。真实 Google 联调需要配置 `GEMINI_API_KEY`，模拟测试不代表已验证云端模型回答质量。

2026-09-17 真实联调：复用项目线上 Gemini 3.8 Flash 配置及出站代理，仅上传仓库合成 PDF。原生 Files 上传成功，模型两轮分别正确回答奶奶种树及花园地点，未调用正文读取工具；结束后删除 Google 测试文件。Word/PPT 转换在本地以外部转换器替身验证缓存与预览接线；本机未安装 LibreOffice，实际转换需生产镜像依赖或本地安装后验证。
