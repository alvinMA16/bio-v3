# 管理后台首版

入口为 `/admin/`，复用现有手机号验证码登录。独立管理 API 位于 `/api/v1/admin/*`。普通账号不会因为知道地址或修改前端状态而获得权限。后台需要 `AUTH_ENABLED=true` 和现有 PostgreSQL；私有预览模式不开放管理 API。

## 授予权限

1. 先用需要授权的手机号正常登录产品，创建账号。
2. 查询该账号 ID：登录浏览器中通过 `GET /api/v1/auth/me` 得到 `id`；也可由部署维护者在数据库中按手机号参数化查询 `bio_auth_users`。不要将手机号、令牌或数据库凭证提交到 Git。
3. 在本地被忽略的 `.env` 或生产 `/srv/bio-v3/shared/production.env` 中配置：

```dotenv
AUTH_ENABLED=true
ADMIN_OPERATOR_USER_IDS=<账号ID>,<另一个账号ID>
ADMIN_VIEWER_USER_IDS=<只读账号ID>
```

`ADMIN_OPERATOR_USER_IDS` 允许读取和重试失败的记忆任务；`ADMIN_VIEWER_USER_IDS` 允许读取用户原文、文稿、资料、记忆与运行记录，但不能重试。两种列表都为空时所有账号均无管理权限。同一个 ID 同时出现时采用 operator 权限。这里使用实际账号 ID，不接受手机号、验证码、登录令牌或昵称。

本地修改环境配置后重启 API。生产环境变量是容器创建时注入的，修改文件后需要按 [生产部署说明](../infra/production/README.md) 重新创建 API 容器；单纯 restart 不加载新的 env_file。上线前通过正常发布流程部署这一版本。本次实现不会自动授权任何实际账号或修改生产配置。

权限由每个请求的 AdminGuard 在服务端核对，先验证现有登录会话，再匹配角色名单。移除名单并重新加载配置后，已有登录令牌也不能继续访问后台；退出登录和会话过期同样立即拒绝管理请求。管理页面与产品共用登录会话，没有另一个永久管理密钥。

## 首版范围

- 概览：账号数、北京时间当日有非空用户消息的人数、滚动七日通话和新增文稿、记忆任务积压及采集到的 Agent 失败。
- 用户：手机号/ID 搜索、服务端分页、默认手机号脱敏；详情分为使用记录、文稿、资料、长期记忆、整理任务。
- 会话：原文分页、工具执行记录、Trace 分页、模型用量、已有播放回执；支持 URL hash 深链接。
- 文稿：复用 DocumentReader；当前正文、分页版本索引、历史正文并排阅读和修改会话跳转。没有管理员编辑/恢复正文的接口。
- 资料：按用户读取本地索引、显示识别状态及正文、下载原件。下载强制 attachment，经管理员及目标用户检查，不复用普通用户文件 Cookie。
- 记忆：概要、分类条目、版本及原始依据；来源可跳回会话。没有管理员直接修改记忆的接口。
- 任务：状态筛选、失败任务重试、前序任务阻塞提示；重试重新排队，保持 worker 的同用户串行规则，不强制越序执行。
- 服务与日志：数据库连接、配置摘要、已采集 Agent/语音异常、管理操作审计。外部模型/语音服务未主动调用探测。

## 数据与采集边界

文稿继续使用 bio_documents/bio_document_revisions；后台不产生另一份正文。记忆与原文沿用原表。资料原件支持 OSS，但元数据仍依赖现有单实例本地卷，列表先读取该用户目录再分页；未实施全局资料索引迁移。

新增 bio_run_metrics 保存新的已归属 Agent 运行的状态、耗时、模型、用量和可估价部分，成功、失败和取消均尝试记录；历史调用不补算。未知价格保存 null，不将零费用估算冒充免费。统计仅包含现有定价覆盖的 Agent 模型调用，不包含 ASR、TTS、视觉识别、搜索、记忆整理，也不是服务商账单。采集失败仅记安全告警，不让已成功的业务运行因统计失败而失败。后台显示已采集数量与未知价格数量；进程崩溃可能留下缺失记录。

新增 bio_voice_failures 记录已建立通话的语音失败阶段与错误码，不保存音频或凭证。通话尚未建立前的错误、浏览器前端异常和客户端未上报的问题仍不在这一列表。Trace 保留现有本地文件存储，管理端逐行读取并分页；去除常见凭据字段与 Bearer 字符串，但授权人员仍可以查看被审计的用户原文。

新增 bio_admin_audit 记录操作者、动作、目标用户、目标对象及时间，不复制正文或凭证。读取会话列表/原文、Trace、文稿正文/历史、资料内容/原件、记忆概要/依据会记录审计。失败任务重试与审计在同一事务中提交；审计失败则回滚重试。审计表仅提供读取 API。

管理查询使用独立、最多 2 个连接、10 秒 statement timeout 的连接池，不占用原有 12 个记忆连接中的 SDK 保留名额。账号连接池仍为 5，因此单实例配置的连接池上限合计为 19。增加实例前需核算数据库总容量。

## 验证

`apps/api/test/admin.test.mjs` 覆盖所有管理路由的无身份/普通账号/只读角色矩阵、目标用户不匹配、掩码和分页参数、Trace 凭据隐藏、播放关联、未知价格、重试竞争与审计失败回滚、退出后的访问拒绝。数据库测试必须使用独立 `AUTH_TEST_DATABASE_URL`；发布门槛拒绝 skip。`apps/debug-console/test/admin-model.test.mjs` 验证深链接及查询参数编码。

```sh
pnpm typecheck
pnpm build
# 仅指向独立测试库，不使用生产库
AUTH_TEST_DATABASE_URL=postgresql://... MEMORY_TEST_DATABASE_URL=postgresql://... pnpm test:release
```
