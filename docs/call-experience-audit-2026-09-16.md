## 工具实际可用情况

当前服务加载内容工具：switch_mode、update_content、get_content。它们分别负责切换展示模式、写入草稿、读取当前内容。

记忆启用后才会增加 search_call_history、search_memory、read_memory、read_source。因此这两通电话不能用于判断“已有记忆为何检索不好”：运行时没有启用记忆，也没有执行记忆检索。历史 Trace 留在开发磁盘上，并不自动成为 Agent 可读记忆。

## 建议执行顺序

1. 本地先做 A1–A4：记忆和文档基本可用，失败能定位。
2. 完成 A5–A8：动作、对话质量与文稿找回，形成可持续试用的版本。
3. 执行 B1–B3，部署并验收测试环境。
4. 在测试环境开展 C1–C4，修复实际发现的问题，再扩大使用范围。

结论：本次已确认的八类问题都能在本地先处理。真正适合部署后再调整的是公网稳定性、设备差异、长期记忆质量和性能参数；不能指望部署解决“没加载记忆工具”“没有写入正文”或“动作没有设计好”。
