# 通话动作：三阶段和加载保护

## 消失问题

- 逐帧检查六组精灵图：有效帧上半部都有狐狸像素，尺寸与 manifest 一致。未发现有效帧为空；表格末尾的未使用格子不参与播放。
- 原先 Web 和小程序通话页在一个节点上直接替换图片地址，加载期间没有保留旧角色的机制。尚未复现用户那次消失的完整现场，因此不能断定这是唯一原因。
- 两端改为常驻各动作图片，加载成功才允许显示。目标图片慢、失败或加载乱序时，保留上一张已就绪的狐狸；迟到的加载事件不会恢复已经结束的动作。首次进入尚无任何图片就绪时仍需等待初次加载。

## 三阶段

| 阶段 | 原行为 | 本次行为 | 驱动信号 |
| --- | --- | --- | --- |
| 用户说话 | 连续记录，偶尔点头 | 保留：短笔画约 360 ms，间隔性停笔，点头至少间隔 12 秒 | 实际用户语音检测与转写变化 |
| Agent 处理 | 持本静止，偶尔点头 | 慢速记录：笔画约 600 ms，每四次停约 1.4 秒，间隔点头 | Agent 运行、语音识别收尾、语音合成等待 |
| Agent 说话 | 持本口型循环 | 保留：一旦音频实际播放立即停止书写，持本说话 | 实际音频播放状态，不能用模型文本生成结束代替 |

用户插话优先于残余播放；否则实际音频优先于处理状态。等待用户开口保持持本、偶尔点头。减少动态效果的系统偏好保持有效。复用现有素材，不增加动作数量。

## 小动作控制建议

- 主状态由本地运行状态决定，模型不控制帧、播放时钟或三阶段切换。
- 点头使用情境限制和冷却；当前记录循环每至少 12 秒可插入一次。持本等待时 8–14 秒的轻微随机间隔只用于避免机械重复。
- 目前空手待机有眨眼；尚无单独的持本眨眼和微笑素材。本次不将空手眨眼混入持本通话，以免再次反复放下本子。
- 后续优先增加持本眨眼，再考虑微笑。眨眼可用本地节奏调度；微笑应有情境依据，可由模型给出低频情绪提示、本地校验和限频，避免在严肃话题里随机微笑。

## 验证

- Web 41 项、小程序 7 项测试通过；含延迟/失败/乱序加载、长时间帧范围、处理与说话切换回归。
- 全项目类型检查、Web 构建通过；浏览器检查处理/说话阶段。未在微信真机上完成长通话复测，也未复现用户原始消失现场。
- 初次资源全部失败时的独立占位提示、持本眨眼/微笑新素材不在本次实现范围。
