# Agent 行为回归 v1

入口为 `apps/api/scripts/bench-agent.mjs`，案例为 `agent-cases.json`。保留旧 voice-v0.1/v0.2 基线，不混算分数。

13 个案例来自 2026-09-19 体验审查后的去身份化重建及压力变体，不是生产逐字回放。所有案例都已参与开发，统一标记 dev，不能宣称是未见测试集。新增真实问题时补充其通用行为目标及反向案例，避免仅修一种表现：主动但不盘问、尊重结束但不送客、共情但不虚构、精炼但不抢话。原始私有聊天不得提交 Git。

## 运行

```sh
pnpm --filter @bio/api build
# 离线：本机模拟模型响应，仅验证输入、历史、场景、工具及输出链路
node apps/api/scripts/bench-agent.mjs --output /tmp/agent-bench-offline-NEW
# 真实模型：显式启用，产生 API 费用；使用 .env 的 MODEL_PROVIDER 和对应模型配置
node --env-file=.env apps/api/scripts/bench-agent.mjs --live --output bench/voice/runs/agent-NEW
```

output 父目录需存在，目标目录必须不存在。每个案例使用独立临时目录和会话，结束后清理；不实例化 MemoryService，不连接数据库，不读写线上数据。关闭 Google Search，避免这组行为回归受外部搜索变化影响。不要用 offline 回复参与质量评分。

真实运行经过 AgentService → PiSessionFactory → Pi SDK，使用当前编译后的公共 Prompt、动态 bio_runtime_context、实际内容工具及工具循环；不再使用旧 candidate-system.txt。案例评分目标不会发给候选模型。附件是合成的文本资料，不覆盖原生 PDF/图片理解。

完整保留案例提供的多轮历史，但只生成最后一条用户消息之后的回复。这是固定多轮上下文的单步回归，**不是闭环多轮用户模拟**。不能把原对话未来的用户反应接到新回复后冒充自然交流。无数据库记忆；grounding-memory 只检查记忆缺失时的诚实性，不证明断线恢复已修复。数据库恢复和后台记忆整理仍由独立集成测试验证，语义评测需另备隔离数据案例。

## 结果与评审

results.json 保存案例、构建产物及 SHA-256、输入指纹、回复、Trace、模型、usage、成本估计、首字与完整耗时，失败逐题保留并返回非零退出码。离线额外记录实际兼容协议请求以核验上下文。真实运行不会记录密钥；临时 SDK 凭证随目录清理。编译产物快照是实际加载版本，因此运行前必须 build。

修改前后比较时，对同一份案例分别运行各自代码版本，保持模型和配置一致；旧版已归档结果不覆盖。生成输出属于私有结果，保存在被忽略目录。模型质量由语义评审决定，不写问号数、关键词或字数断言来假装判断聊天质量。

每题评审记录：是否满足 rubric.expectation、具体原文证据、仍存在的问题。沿用 intent / grounding / continuity / spoken / pacing / empathy 六维 1–5 分，但以本文件声明的实际工具能力为准，不能套用旧 bench“没有工具”的假设。重点检查：

- intent：是否持续完成用户意图，是否贡献理解、判断或行动，而非泛泛附和。
- grounding：是否增加了未经支持的事实或感受；纠正是否改变了后续理解。
- continuity：是否利用整段历史，包括助手自己造成的问答负担或收尾信号。
- spoken：是否自然可听，长度是否服务内容，而非越短越好。
- pacing：是否共同推进，既不机械盘问也不无故送客；明确结束时是否停下。
- empathy：是否具体理解感受；需要时提炼而非抢话，不用安慰替代回应。

严重事实错误、忽略明确边界、虚构操作单列，不以平均分掩盖。语义评分是研发参考，不是用户总体满意率。要做匿名 A/B 时，由单独的评审材料隐藏版本和模型身份，锁分后解盲；普通逐题检查不得宣称盲评。
