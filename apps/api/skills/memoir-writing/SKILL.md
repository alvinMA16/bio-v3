# 回忆录写作

把值得保存的人生片段写成有具体经历、人物关系和个人声音的文章。可以是一件小事、一段关系或一个阶段，不默认要写完整自传。用户指定的用途、体裁、风格和修改范围优先；讨论方案不等于授权修改正文。

## 范围与视角

先读任务所需的原始讲述与已有文稿。历史摘要用于寻找线索，不代替可取得的原文。明确这篇文章要留下的是谁、什么经历或哪个阶段，以用户意图和素材重心界定范围，不因出现过去的事情就自动进入回忆录写作。

区分事情发生时用户知道、感受到的内容与如今讲述时的理解。两种视角都可以保留，但不能把今天的认识倒写成当时已有的想法。用户没有表达回望或评价时，可以让具体经历本身成立，不要求补一个意义。

## 人物与事件

选择能让人物和关系具体可见的事件、动作、可靠的原话及相处方式，保留用户有辨识度的表达。避免把人物简化成身份、性格标签或泛泛赞美，也不根据行为替他人确定内心动机。

围绕素材中的关联安排段落：可以按时间、人物关系或一个反复出现的事物组织。只交代理解所需的背景，不平均罗列人生节点。关联不等于因果，不把时间相邻的事情自动写成命运转折。

重要事件充分展开，重复经历可以合并转述，但不得把不同时间发生的事拼成一个虚假的现场，也不得将多次谈话拼成一次直接对话。记忆中的空白、矛盾和犹疑可以保留，不用顺滑叙事掩盖不确定性。

## 语言与收束

保留叙述者的口吻与感情分寸，修掉赘词和重复，不让所有回忆都变成同一种怀旧腔。以已有的具体细节承载感情，不用抽象评价替代事件，也不追求每段都煽情。

开头提供适合进入这段经历的切口，结构和篇幅服从素材。结尾可以落在真实片段、仍未解开的疑问或用户已表达的回望上；不强加成长、和解、释怀或人生道理。

## 缺口与交付

遵守基础真实性规则。先从已有资料补足必要背景；确有影响文章重心的私人信息缺口时，只围绕一个重要点自然追问。用户要求直接写时，使用现有素材形成成立的文章或片段，不为完整性继续盘问。

交付前对照原文检查：重要细节是否保留、人物是否通过事件呈现、关系与事件先后是否准确、当时与如今的视角是否混淆、语言是否仍像用户，以及是否添加无来源的心理、因果或意义。先修订，再通过文稿工具交付；不把检查过程交给用户。

长文分批保存前先形成整体结构，保存有意义的开头后继续完成全文，不将人生履历、摘要或提纲当成完成稿。口头说明保持简短，文章长度独立服从任务。
